# 08 · 上电无输出问题的定位过程与结论

> 现象：两块板烧 BL + APP 后**上电完全没反应**（LED 不闪、LCD 无背光、串口无输出）。
> 本文记录定位过程、真实根因与修复。**结论由实测得出，不是推断。**

---

## 1. 定位过程（逐步排除）

用"能观察到的最小系统"逐层剥离，每一步都给出**可判定的现象**：

| 步骤 | 固件 | 观察 | 结论 |
|---|---|---|---|
| 1 | BL + APP | LED 不闪、串口无输出、LCD 无光 | 故障现象 |
| 2 | `BL_bare_blink_TEST.hex` v1（LED 15ms 快闪） | "闪了一下就没了" | **MCU 能执行代码**；但周期太快无法判读（设计缺陷） |
| 3 | v2（LED 1.5s 长亮 + HSI 16MHz + 串口） | LED 爆闪 1.5s 后停；串口无输出 | 延时循环被编译器**优化删除**导致爆闪；串口发送是**死等**导致整体卡死（两处均为设计缺陷） |
| 4 | v3（volatile 延时 + 串口超时 + 1/2/3 心跳） | **串口收到 820 字节、LED 1-2-3 循环** | ✅ MCU / 时钟(HSI) / USART1 / LED / 烧录链路 **全部正常** |

### 决定性事实

v3 固件**刻意不使用 HSE**（直接 HSI 16MHz 作系统时钟），一切正常；
而 BL 与 APP 都依赖 `HSE 8MHz → PLL → 150MHz`。

---

## 2. 根因

`ota/bootloader/Core/Src/bl_clock.c`：

```c
RCC_OscInitStruct.OscillatorType = RCC_OSCILLATORTYPE_HSE;
RCC_OscInitStruct.HSEState       = RCC_HSE_ON;
...
if (HAL_RCC_OscConfig(&RCC_OscInitStruct) != HAL_OK)
{
  Error_Handler();          /* <-- 关中断 + 死循环 */
}
```

`Error_Handler()` 是**关中断死循环**。因此一旦 HSE 起振失败：

* 不会打印任何日志（串口还没初始化就卡住了）
* LED 无反应（诊断代码在时钟配置之后）
* APP 同理（同一个 HSE 配置）→ 两块板都"没反应"

**这也解释了为什么"什么都没输出"而不是"输出错误信息"**——卡点在日志初始化之前。

---

## 3. 修复

### 3.1 BL：HSE 失败自动回落 HSI + 上报时钟源

`bl_clock.c` 改为：

```
HSE + PLL  -> 150MHz（原行为）
   ↓ 失败
HSI16 / M=4 = 4MHz  ->  x N=75 = 300MHz VCO  ->  / R=2 = 150MHz（回落路径）
   ↓ 失败
Error_Handler()（真的没救了）
```

PLL 参数均落在合法窗口内（VCO 输入 2.66~16MHz、VCO 输出 96~344MHz），
且**与 HSE 路径同为 150MHz**，因此串口时序与非回落情况完全一致。

新增 `BL_ClockSource()`，`main()` 在 UART 就绪后立即上报：

```
BL: clock HSE+PLL 150MHz OK                  <- 晶振正常
BL: !! HSE FAILED -> running on HSI+PLL 150MHz  <- 晶振起振失败（板级问题）
```

**这条日志是最后的判据**：它把"晶振坏了"与"代码配错"一次问清。

### 3.2 裸机诊断固件保留

`BL_BARE_BLINK=1` 仍保留在 `ota/bootloader/Core/Src/main.c` 中，
作为"MCU 到底有没有在跑"的最终手段（不依赖 HSE、不依赖 HAL）。
产出物：`firmware/BL_bare_blink_TEST.hex`。

---

## 4. 如果日志显示 `HSE FAILED`

说明 **HSE 起振失败是板级/配置问题**，按可能性排查：

| 可能原因 | 如何确认 |
|---|---|
| **板上没有 8MHz 晶振**（或未焊/虚焊） | 看板子晶振位置是否有元件；量晶振两脚 |
| 晶振有，但负载电容不匹配 / 起振慢 | 用示波器看晶振脚是否有 8MHz 正弦 |
| `HSE_VALUE` 宏与实际晶振频率不符 | 检查 `stm32g4xx_hal_conf.h` 的 `HSE_VALUE`（应为 `8000000U`） |
| 晶振损坏 | 换一片晶振 |

> **若确认板上没有晶振**：本方案可以改成**纯 HSI 运行**（不依赖 HSE），
> 代价是时钟精度（HSI ±1%，HSE 通常 ±20ppm）。对 CAN 而言 ±1% 在 500kbps 下
> 接近容差边缘，建议先确认再做决定——CAN 位时序对时钟精度较敏感。

## 5. 我在这次定位中犯的错误（记录以免重犯）

| # | 错误 | 后果 | 修正 |
|---|---|---|---|
| 1 | 把串口助手"关闭串口"按钮当成"串口未打开"（方向理解反了） | 据此得出错误结论、浪费一轮 | 该按钮显示的是**点击后会执行的动作** |
| 2 | 诊断固件延时仅 15ms，肉眼无法判读 | "闪了一下就没了"，无法区分正常与异常 | 改为 1/2/3 次分组心跳 + 1 秒间隔 |
| 3 | 延时用 `uint32_t i = 4000; while(i--) {__NOP();}`（无副作用） | 被编译器**整体删除**，延时瞬间返回 → 爆闪 | `volatile` 计数器 + 运行期上界（已用反汇编确认循环存在） |
| 4 | 串口发送 `while(TXE==0)` **死等** | 串口异常时整体卡死，LED 也停，掩盖了真实状态 | 加超时；LED 心跳独立于串口 |
| 5 | `bl.sct` 域曾被 Keil 覆盖回 32KB，我误以为改动生效 | BL 链接报"空间不足"，排查数轮 | 加 `ota/scripts/fix_bl_region.py` 固化 |
| 6 | BL 诊断延时循环被**完全展开**，`main.o` 从 1KB 涨到 24KB | BL 顶爆分区 | 运行期上界 + `noinline` |
