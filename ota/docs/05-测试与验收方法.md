# 05 · 测试与验收方法

> 本工程的可验证性要求很高：OTA 一旦半途失败就是"变砖"。下面的用例按**风险从低到高**排列，
> **严禁跳过前 4 组直接做整机升级**。每组都给出可观察的判据，不靠"感觉正常"。

---

## 0. 测试环境与前置检查

| 项 | 要求 |
|---|---|
| 上位机 | `tools/ota_host.py`（本项目新增）；或 USB-CAN 适配器 + 任意 UDS 工具 |
| 节点 | 板 B 烧录"目标节点固件"；板 A 可选（隧道模式需要） |
| 串口 | USART1 `PA9/PA10` 115200 8N1（看 BL/APP 日志） |
| CAN | 500 kbit/s，两端各 120 Ω 终端电阻（**缺终端电阻是升级失败的第一大原因**） |
| 工具 | Keil MDK（烧录 BL 与 APP）；可选 SWD 调试器（救砖） |

### 0.1 烧录顺序（**必须按此顺序，否则首块板会"看起来变砖"**）

```
1. 先烧 Bootloader（IROM1 = 0x08000000，size 0x800）        → 此时无 APP，上电进 recovery，串口打印等待刷写
2. 再用上位机把 APP 镜像刷进 Slot A                          → 复位后 BL 校验 A 并跳转
3. 之后所有升级都走 OTA，不再需要 SWD
```

> ⚠️ 如果先烧 APP（链接在 `0x08000800`）而没有 BL，`0x08000000` 处是空的（全 `0xFF`），
> CPU 复位后取到非法栈顶/复位向量会 **HardFault 死机**。**BL 必须第一个烧。**

### 0.2 验收用固件对

准备两个版本，版本号写在镜像头里，便于在 `22 F1 82` 里区分：

| 文件 | 版本 | 内容差异 |
|---|---|---|
| `app_v1.0.bin` | 1.0 | 基线固件 |
| `app_v2.0.bin` | 2.0 | 改一处可见行为（例如 `CAN_APP_VERSION` 改 "3.1.0"，或让 LED 闪烁周期变化），**确保能肉眼/串口区分** |
| `app_bad_crc.bin` | 2.0 | 同 v2.0，但**故意把镜像头 `payloadCrc` 改错**（用于校验失败用例） |
| `app_suicide.bin` | 2.0 | 同 v2.0，但 APP 里 `Ota_Task()` 的自检条件永远不满足（例如把 `CAN_GetStats()->rxCount > 0` 改成 `> 0xFFFFFFFF`）—— 用于**回滚用例** |

打包命令（镜像头由上位机生成）：

```bash
python ota/tools/ota_host.py --pack app.bin --load-addr 0x0800C080 --version 2.0 -o app_v2.0.ota
```

## 1. 组 1：静态/离线自检（无硬件）

| 用例 | 步骤 | 期望 |
|---|---|---|
| 1.1 上位机单元测试 | `python ota/tools/test_ota_host.py` | 全绿；含 CRC32 向量 `0xCBF43926` |
| 1.2 Bootloader 静态自检 | `python ota/bootloader/verify_bl.py` | 全绿；逐条打印 10 项不变量证据 |
| 1.3 分区一致性 | 人工核对 `ota/common/ota_common.h` 的地址与 01 号文档表格 | 完全一致；头文件编译期 `#error` 全不触发 |
| 1.4 镜像往返 | `--pack` 后再 `--parse` 同一文件 | 头部字段与 CRC 自洽，`hdrCrc` 校验通过 |
| 1.5 干跑 | `python ota/tools/ota_host.py --dry-run app_v2.0.ota` | 打印完整报文序列：`10 03` → 预检 → `34` → **210 个 `36`（每块 1016B）** → `37` → `31 01 FF01` → `31 01 FF02` → `11 01`；最后一块长度 ≤1016 |

**判据**：1.1/1.2 退出码为 0 且输出中不存在 `FAIL`。

## 2. 组 2：Bootloader 单独验证（不碰 APP）

| 用例 | 步骤 | 期望结果 |
|---|---|---|
| 2.1 recovery 启动 | 只烧 BL，上电 | 串口打印 BL 版本/状态；无 HardFault；Can 保持在线；`22 F1 84` 回 `62 F1 84 07` |
| 2.2 启动窗口 | BL 正常态下，复位后 **1 秒内**发 `10 03` | 设备**不跳转** APP，留在 BL 应答（证明启动窗口生效） |
| 2.3 窗口外跳转 | 复位后等 2 秒再发 `10 03` | 已跳转 APP；若无 APP，反复打印 recovery |
| 2.4 保护区（**关键**） | 发 `34 00 44 08 00 00 00 00 00 10 00`（目标 `0x08000000`） | 严格回 NRC `31`；**绝不擦到 BL 区** |
| 2.5 目标槽约束 | 在 BL 里让 `F181` 指示活动槽=A，然后请求写 A（`0x0800C080`） | 回 NRC `22`（不许写活动槽） |
| 2.6 块序号校验 | 手工发 `36 00 ...`（序号 0） | 回 NRC `73` |
| 2.7 超长长度 | `34` 声明 size > `OTA_IMG_MAX_PAYLOAD` | 回 NRC `31` |
| 2.8 会话约束 | 默认会话（未发 `10 03`）直接发 `34` | 回 NRC `22` |
| 2.9 CRC 自检 | 上电日志 | 无 `BL: crc self-test FAIL` |

> **2.4 是本方案的生命线**：这条用例失败意味着 BL 区可被 OTA 擦除，**必须停下来修代码，不允许继续**。

## 3. 组 3：APP 侧服务验证（先不真刷）

| 用例 | 步骤 | 期望 |
|---|---|---|
| 3.1 能力与状态 | `22 F1 84` / `22 F1 80` / `22 F1 81` | 分别回 `07`、`00/01`、`00/01` |
| 3.2 目标槽互斥 | 在 APP（运行 A）里发 `34` 指向 A 槽 | NRC `22` |
| 3.3 正常下载 A→B | 刷 `app_v1.0.bin` 到 B 槽 | 全程 `76 <seq>` 无 NRC；`31 01 FF01` 回 `00` |
| 3.4 CRC 不符 | 用 `app_bad_crc.bin` 刷，走到 `31 01 FF01` | 回结果码 `01`（CRC 不符）；**`FF02` 必须拒绝**（回 `01`） |
| 3.5 长度不符 | 人为少发最后一块再 `37` | `FF01` 回结果码 `02` |
| 3.6 块序号跳变 | 跳到 seq+2 | 回 NRC `73`，且下载状态可继续（重发正确序号应成功） |
| 3.7 续传 | 传 50% 后断线，重连后 `--resume N` | 从第 N 块继续，最终 `FF01` 通过 |

**3.4 的关键**：CRC 不符时**绝不能**置 TRIAL。这是"坏固件不上线"的最后一道闸门。

## 4. 组 4：端到端升级 + 回滚（核心验收）

### 4.1 用例 A：正常升级 A → B

```
前置：设备运行 app_v1.0（Slot A），22 F1 82 回 A=01.00 B=00.00

1. python ota/tools/ota_host.py --port COMx app_v2.0.ota --precheck --verify
2. 观察串口日志：擦除 → 210 块 → 校验通过 → 激活 → 复位
3. 复位后 Bootloader 日志应出现 state=TRIAL_B、trialLeft 3→2
4. 跳转 APP_B，APP 日志打印 "ota: TRIAL boot (slot 1, left 2)"
5. 3 秒后 APP 自检通过 → 打印 "ota: trial committed (IDLE)"
6. 再读 22 F1 80/81/82：state=01(IDLE_B)，slot=01，A=01.00 B=02.00
```

**通过判据**：第 6 步读到 `IDLE_B` 且 B 版本为 2.0；断电重上电后仍运行 B 且**不再**进入 TRIAL。

### 4.2 用例 B：回滚（**本方案最有价值的用例**）

```
前置：设备运行 app_v1.0（Slot A）
1. 刷 app_suicide.bin（CRC 正确、但 APP 自检永不通过）到 Slot B
2. FF01 通过 → FF02 激活（state=TRIAL_B, trialLeft=3）→ 11 01 复位
3. 第 1 次启动：BL 打印 TRIAL_B，trialLeft 3→2，跳转 APP_B；APP 自检不通过，不落定
4. 手动复位 2 次：trialLeft 2→1→0
5. 第 4 次启动：BL 打印 "trial exhausted, rollback to A"，state=IDLE_A，trialLeft=0
6. 跳转 APP_A，串口出现 v1.0 的启动日志
```

**通过判据**：**无需人工干预**，设备自动回到 v1.0；`22 F1 80` 回 `00`（IDLE_A）、`22 F1 82` 回 A=01.00。

> 这条用例证明的不是"能升级"，而是**"升级失败不会让设备变砖"**。它是本方案的核心验收项。

### 4.3 用例 C：传输中途掉电

```
1. 刷到约 50% 时直接断电
2. 重新上电
3. 期望：BL 读到 state=IDLE_A（控制区未被改动），校验 Slot A 通过 → 正常运行 v1.0
4. 再次发起完整升级 → 应能正常完成（目标槽被重新擦除，残留数据无影响）
```

**判据**：第 3 步必须正常启动旧固件。**若此时设备卡在 BL 或反复复位，说明控制区写入不是掉电安全的，需要回到 04 号文档 §2 检查写策略。**

### 4.4 用例 D：显式回滚

```
1. 设备运行 app_v2.0（IDLE_B）
2. 发 31 01 FF03（显式回滚）
3. 期望：回结果码 00；11 01 复位后运行 v1.0（Slot A）
```

### 4.5 用例 E：控制区损坏自愈

```
1. 用调试器把 0x08000000~0x080007FF 与 0x08040000~0x080407FF 全部写成 0x00
2. 上电
3. 期望：BL 发现 4 个候选全部无效 → 按默认值重建（IDLE_A、两槽 size=0）→ 进入 recovery
         串口打印等待刷写；能正常被上位机刷写 Slot A
```

**判据**：**绝不能死锁**。这是"配置区被静电/误操作破坏"场景的兜底。

## 5. 性能与压力测试

| 用例 | 方法 | 期望 |
|---|---|---|
| 5.1 实测总耗时 | 记录 `--verify` 全程墙钟时间 | CAN 直连应与 03 号文档 §5.3 的 **~9 s** 估算同量级（±50%）；若走串口隧道则约 ~74 s。**明显更慢时先查 STmin、`--block-size` 是否被调小、以及是否走了隧道** |
| 5.2 总线负载共存 | 升级期间另一对板同时跑 0x321/0x322 心跳 | 升级成功，且心跳**不中断**；`F002` 统计里 `rxOverruns` 不增长 |
| 5.3 环形缓冲余量（**优化后重点**） | 读 `22 F002` | `rxOverruns == 0`；`txEvtLost == 0`。1016B/块会产生 146 个 CF，若主循环被阻塞就会在这里暴露 |
| 5.4 连续升级 10 次 | 循环 A→B→A… 交替 | 每次都成功；`seq` 单调增长；无一次进入 recovery |
| 5.5 低波特率 | 切到 250 kbit/s（两板同步）后刷写 | 能成功（更慢，验证与速率解耦） |
| 5.6 IWDG 边界 | 刷写全程观察是否复位 | **不得出现非预期复位**；若出现，检查 `Ota_PageFlush` 前的 `HAL_IWDG_Refresh` |

## 6. 常见故障与定位

| 现象 | 最可能原因 | 定位手段 |
|---|---|---|
| 上位机收不到任何应答 | ① CAN 无终端电阻 ② 过滤器没放开 `0x7E8` ③ 节点还在 BL 启动窗口外已跳 APP 但 APP 未初始化 UDS | 读 `F002` 看 `rxCount` 是否增长；用 `sniff` 抓包 |
| `diag: isotp timeout` | STmin 太小导致对端跟不上 / 总线错误 | 看 `F002` 的 `errPassiveCount`、`busOffCount` |
| 擦除后校验总失败 | 目标槽地址算错（漏了 32B 镜像头） | 核对 `loadAddr == 槽基址 + 0x20` |
| 升级成功但复位后仍跑旧固件 | `FF02` 未成功 / 控制区没写进去 | 复位前读 `F180`，应为 `TRIAL_x` |
| 复位后直接进 recovery | 新镜像的 SP/复位向量非法 | BL 日志会打印具体 `OTA_ERR_*`；读 `F183` 比对 CRC |
| 反复"升级→回滚" | APP 自检条件太严（CAN 未真正通信） | 看 APP 日志 `ota: self-check not passed` |
| 设备完全无响应（疑似变砖） | BL 被擦 / 选项字节被改 | 用 SWD 连接读 `0x08000000` 是否为有效向量表；重新全片擦除后按 §0.1 重烧 |
