# APP 启动重启循环 + CAN 发送挂死 —— 诊断报告

> 日期：2026-10-10（当日晚间更新，结论已深化）
> 状态：**重启循环已解除，板子可稳定运行**；**CAN 发送挂死仍未解决**
> 影响：这是本项目的头号阻塞缺陷 —— 它导致串口命令行、OTA 全链路从未可用

---

## 一、结论速览

### 1.1 启动重启循环（已解除）

APP 启动后卡死 → 被 IWDG 每 ~3.1 秒复位 → 无限循环 → **主循环从未运行**，
因此 `Console_Task()` 从未执行，表现为"串口发命令零响应"、OTA 无法进行。

**卡点已精确定位到 `HAL_FDCAN_AddMessageToTxFifoQ` 的最后一句：写 `TXBAR`（请求发送）。**

### 1.2 CAN 发送挂死（未解决，是当前唯一的功能性阻塞）

**只要写 `TXBAR` 的请求位（真正请求发一帧），AHB 总线就被挂住约 3 秒直到复位。**

- 写 `TXBAR = 0`（不请求）完全无害 ✓
- 写 `TXBAR = 1`（请求发送）→ 挂死 ✗

挂死期间的特征：**无中断、无 HardFault、无 Error_Handler，且 SWD 也连不上**
（`mode=normal`/`hotplug` 均失败，`mode=UR` 可以）—— 这正是"总线被外部持有"的特征。

### 1.3 串口接收（RX）物理不通（独立问题，属硬件）

连续发送 145 条命令后，接收中断计数 `rxIrq` 仍为 **0**。
而 USART1 的全部配置经实测确认无误（见 §4）—— **信号没有到达 PA10**。

## 二、根因定位过程（逐步收窄）

| 步骤 | 手段 | 收窄结果 |
|---|---|---|
| 1 | 启动打点 A~H | 卡点在 `CAN_Init` 之后、`CAN_SelfTest` 之内 |
| 2 | 在 `CAN_SelfTest` 内打点 S1~S6 | 卡点在 `CAN_Send()` 内 |

## 三、本轮处置（让板子先能稳定运行）

| 改动 | 文件 | 说明 |
|---|---|---|
| 移除自检的回环发送 | `can.c` `CAN_SelfTest` | 保留回环配置与恢复流程（S1/S2/S5/S6） |
| 周期心跳临时禁用 | `main.c` | 新增编译期开关 `CAN_HEARTBEAT_ENABLE`（默认 0）；修复 CAN 后改回 1 |
| FDCAN 内核时钟改 HSE | `stm32g4xx_hal_msp.c` | 8MHz 稳在任何上限内，避免 150MHz 超限嫌疑 |
| 位时序按 8MHz 重算 | `can.c` | 16tq/位（NTSEG1=13），分频 125k→4 / 250k→2 / 500k→1；1M 在 8MHz+16tq 下不可达，表中置 0 显式失败 |

**验证结果：板子持续运行 14 秒无复位，主循环正常（`[uart]` 诊断每 3 秒一次）** ✔

## 四、串口接收（RX）物理不通的证据链

| 检查项 | 实测值 | 判读 |
|---|---|---|
| `USART1->CR1` | `0x002D` | UE(bit0)\|RE(bit2)\|TE(bit3)\|RXNEIE(bit5) 全对 ✓ |
| `USART1->BRR` | `0x0516` | 115200 @150MHz ✓ |
| `NVIC->ISER[1]` | `0x00000020` | bit5 = USART1_IRQn(37) 已使能 ✓ |
| `huart1.RxState` | `0x22` | HAL_UART_STATE_BUSY_RX（`Receive_IT` 已挂起）✓ |
| `GPIOA->MODER` | `0xABEBFFFF` | PA10 = AF 模式 ✓ |
| `GPIOA->IDR` bit10 | `1` | PA10 空闲态为高 ✓ |
| **连续发送 145 条命令后 `rxIrq`** | **`0`** | **接收中断从未触发 ✗** |

**结论**：MCU 侧配置与中断链路全部正确，但信号未到达 PA10
→ **CH340K 的 TX 没有接到板子的 PA10**（接线 / 焊接 / 转接板问题）。

> 验证方法：接好线后重上电，键入任意字符，`[uart]` 诊断行的 `rxIrq` 应递增；
> 同时控制台应能响应 `version` / `help`。

## 六、经验教训（值得固化的三条）

1. **静默的故障处理函数是最大的坑**：本项目 `HardFault/MemManage/BusFault/UsageFault`
   四个处理函数原本都是 `while(1)`，把"有信息"变成"零信息"，导致"每 3 秒重启"
   这个现象排查了很久。**本轮已全部改为打印 CFSR/HFSR/BFAR/PC 后再停机。**
2. **看日志必须核对时间戳**：我曾把两个打点之间"调试打印的耗时"误当成"写操作耗时"，
   据此得出"HSE 修好了"的错误结论，多绕了好几轮。T3→T4 之间实际相隔 3.12 秒。
3. **"工具报成功"≠"内容正确"**；**多板环境必须先确认身份**（本项目曾把 COM5 当板1
   分析了一小时）；**`.gitignore` 规则要用 `git check-ignore` 实测**。
