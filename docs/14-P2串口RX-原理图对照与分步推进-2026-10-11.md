# P2「串口 RX 不通」——原理图对照 + 分步推进清单

> 日期：2026-10-11
> 角色：嵌入式系统架构顾问（OTA/Bootloader 全链路）
> 触发：用户提供 **SWD + USART1 原理图**（J4 CON4-X2），并指出
> **CAN 双机通信 + UDS 项目** 与 **Modbus RTU 项目** 用同样的 USART1/PA9/PA10
> **实机跑通、串口正常**。
> 结论：**P2 根因已从"推测为硬件"升级为"由原理图 + 两个已跑通项目源码双重证实"**。

---

## 〇、一句话结论

**这块板子上没有板载 USB 转串口芯片。** PA9/PA10 只是被引到 J4 调试座上，
必须用**外接 USB-TTL 模块**手动接线；而且**只能接 3 根**：
`TXD→PA10`、`RXD→PA9`、`GND↔GND`，**其余线（尤其 DTR/RTS）一律拔掉**。

我此前的 `edges/20ms=0`（PC 发数据时 PA10 零跳变）正是"**PC 的 TX 没有物理接到 PA10**"
的直接结果 —— 现在有了原理图，可以精确定位是哪一段断了。

## 一、原理图解读（用户提供的 J4 图）

### 1.1 J4 = CON4-X2，2×4 调试座

| 引脚 | 网络 | 说明 |
|---|---|---|
| 1 | SWCLK → **PA14** | SWD 时钟 |
| 2 | SWDIO → **PA13** | SWD 数据 |
| 3 | **GND** | 地 |
| 4 | **5V** | 5V 电源 |
| 5 | **PA10 = USART1_RX** | **MCU 的接收脚** |
| 6 | **PA9 = USART1_TX** | **MCU 的发送脚** |
| 7 | **R4 (1.5 kΩ) → RST** | 复位（经限流电阻） |
| 8 | **3.3V** | 3.3V 电源 |

### 1.2 从原理图能直接读出的三个关键事实

| # | 事实 | 推论 |
|---|---|---|
| **①** | **J4 上没有 CH340/CP210x 之类的 USB 转串口芯片** | **不是板载 USB 转串口**！PC 要连串口，**必须外接 USB-TTL 模块** |
| **②** | PA9/PA10 是**裸 MCU 引脚**直接引到排针 | 接线方向/接触/共地全部由**手工接线**决定，易错 |
| **③** | **pin7 经 R4=1.5 kΩ 接 RST** | 这是"**一键下载电路**"的残留：CH340 的 **DTR/RTS → RST/BOOT0** |

> ⚠️ 第 ③ 条解释了历史上那个"打开串口/写数据就复位板子"的现象 ——
> 外部 USB-TTL 的 **DTR/RTS 若接到 J4 的 RST 网络**，PC 一打开端口就会拉那个脚。
>
> **好消息**：实测两板 option bytes 已是
> `nSWBOOT0=0, nBOOT0=1`（**BOOT0 已失效，任何复位都从 Flash 启动**），
> 所以"复位"已不会把芯片带进系统 bootloader。**但复位本身仍会发生**（握手瞬间）。

## 二、两个"已跑通项目"的交叉证据（最强证据）

用户说 CAN 双机通信 + UDS 项目、Modbus RTU 项目**用同样引脚且串口正常**。
我在工作区找到了这两个项目的**源码与文档**，逐条核对：

### 2.1 `工业数据采集终端`（Modbus RTU 血统）—— `BSP/app_board_cfg.h`

源码里写得**极其明确**（原文引用）：

```c
/* 5. Console - USART1 on PA9(TX) / PA10(RX), AF7                            */
/* There is NO on-board USB-UART bridge.  PA9/PA10 are broken out to J1 pin
 * 11/12 and also to J4 (2x4 debug header shared with SWD).  An external
 * USB-TTL adapter is required. */
#define CONSOLE_TX_PIN           GPIO_PIN_9
#define CONSOLE_RX_PIN           GPIO_PIN_10
#define CONSOLE_GPIO_AF          GPIO_AF7_USART1
```

**逐字吻合用户的原理图**：J4 pin6/5 = PA9/PA10。

### 2.2 该项目 README 的"上板接线（丝印终审版，实机验证）"

```
- USB-TTL → USART1（PA9/PA10）：⚠️ 只接 3 根：TXD→PA10、RXD→PA9、GND↔GND；
  DTR / RTS 等其余线一律拔除——实机踩坑确认：DTR/RTS 接上会"打开串口即复位板子"
  甚至导致 MCU LOCKUP
- 两板 option bytes 已固化 nSWBOOT0=0 + nBOOT0=1（2026-10-11，实机排障产物）
```

### 2.3 该项目 `docs/迁移说明.md §18.3` 的踩坑实录（与本项目一模一样）

| 实验 | 结果 |
|---|---|
| "只打开" COM7（A 板线） | **A 板复位**（`s_poll_count` 归零）|
| 复位原因取证 | 每次都是 **PINRSTF**（`RCC_CSR` bit26）|
| **`dtr=False` 打开后** | **复位不再发生，读到完整启动流** ✅ |
| 读数次后进入 **LOCKUP** | NRST 脏信号 → 复位竞争锁死 |

**修线指引（原文）**：
> USB-TTL **只接 3 根**：`TXD→板 PA10`、`RXD→板 PA9`、`GND↔板 GND`；
> **DTR / RTS / CTS / DSR / VCC（若非供电）全部拔除**。

**且 §18.5 记载"根治"手段**：`STM32_Programmer_CLI -ob nSWBOOT0=0 nBOOT0=1`
—— **本项目两块板已经是这个配置**（我实测确认）。

### 2.4 引脚分配总表（`docs/07` §3，四方交叉核对后的结论性修订）

| 功能 | 信号 | 引脚 | AF | 物理位置 |
|---|---|---|---|---|
| **Console** | USART1_TX / RX | **PA9 / PA10** | `GPIO_AF7_USART1` | **J1 pin 11/12；同时引到 J4 pin 6/5** |
| CAN | FDCAN2_RX/TX | PB12/PB13 | AF9 | 跳线帽 CAN 组 |
| SWD | PA13(IO)/PA14(CLK) | PA13/PA14 | AF0 | J4 pin 2/1 |

> **⟹ 两个项目与本项目用的是同一组引脚、同一套 HAL 配置；
> 他们能跑通，说明"PA9/PA10 + AF7 + 115200"这条软件链路是验证过可行的。
> 所以本项目 P2 的问题**100% 在物理接线**（或那个 USB-TTL 模块本身）。**

## 三、为什么"软件侧"可以被彻底排除（证据汇总）

| 检查项 | 实测值 | 判定 |
|---|---|---|
| PA10 是否配成 AF7 | `MODER=ABEBFFFF` → PA10 nibble = 7 | ✅ 正确 |
| PA10 空闲电平 | `IDR` bit10 = 1 | ✅ 空闲高，正常 |
| USART1 使能 + RX 使能 | `CR1=0x002D` = UE\|RE\|TE\|RXNEIE | ✅ 正确 |
| 波特率 | `BRR=0x0516`（PCLK2 150 MHz / 115200） | ✅ 正确 |
| RX 中断使能 | `ISER1=0x00000020`（bit5 = USART1_IRQn=37） | ✅ 正确 |
| **PA10 电平跳变** | **`edges/20ms = 0`**（PC 连发 5 组数据期间） | 🔴 **信号根本没到** |
| **RX 中断计数** | `rxIrq = 0` | 🔴 从未触发 |
| HAL 状态 | `RxCnt=1`（等 1 字节中） | 正常（`BUSY_RX`）|
| TX↔RX 短接回声 | 写入后收回 0 字节 | ✅ 无短接 |

**软件侧全绿，物理侧零信号 ⟹ 定位在接线。**

## 四、⚠️ 一个必须先搞清的前提问题

**你说的"板载 USB 转串口（集成在 USB 线上）"，与原理图存在矛盾。**

原理图显示 J4 上**只有裸排针**（PA9/PA10），**没有板载 USB 转串口芯片**。
而你现在插在 PC 上的是**两个独立的 CH340K 外接模块**（COM3 / COM5）。

所以请确认你实际的连接方式属于哪种：

| 可能 | 描述 | 需要的动作 |
|---|---|---|
| **A. 外接 USB-TTL 模块** | 一条 USB 线 → 一个 CH340K 小板 → **杜邦线**接到 J4（或 J1） | 检查杜邦线：`TXD→PA10`、`RXD→PA9`、`GND↔GND`；**DTR/RTS 必须拔掉** |
| **B. 板子自带 USB 口做串口** | 板上 USB-C 经某芯片转 TTL | ⚠️ 与原理图不符 —— 需再对照一次板子实物 |
| **C. SWD 调试座的 3.3V/5V 供电线顺带接错** | — | 检查是否把 VCC 接到了 PA9/PA10 |

> **判据**：如果 USB-TTL 的小板上除了 TXD/RXD/GND 之外还插了 **DTR/RTS**，
> 那基本可以断定 RX 不通就是被这两根线搞坏的（历史踩坑明确记录）。

### 步骤 1：把接线收窄到"已知正确的 3 根" ⭐ 关键

**目标**：排除 DTR/RTS 干扰，建立最小可信链路。

**动作**（以板1 / COM3 为例）：
1. 找到 COM3 对应的那个 USB-TTL 模块
2. **只保留 3 根杜邦线**：
   - 模块 `TXD` → 板 **J4 pin5（PA10）**
   - 模块 `RXD` → 板 **J4 pin6（PA9）**
   - 模块 `GND` → 板 **J4 pin3（GND）**
3. **拔掉**：DTR、RTS、CTS、DSR、**VCC/5V/3.3V（若板子另有供电）**
4. 若杜邦线是"排针直插 J4"：注意 J4 是 **2×4**，引脚顺序是
   左侧 1/2/3/4（上→下）、右侧 5/6/7/8（上→下）

**判据（跑我提供的验证脚本）**：
```bash
"C:/Users/13925/.workbuddy/binaries/python/versions/3.13.12/python.exe" \
  tools/p2_rx_probe.py --port COM3 --secs 12
```
脚本会：打开串口 → 连发 5 组数据 → **同时读 MCU 的 `edges/20ms` 与 `rxIrq`**。

| 现象 | 结论 | 下一步 |
|---|---|---|
| **`edges/20ms > 0` 且 `rxIrq > 0`** | ✅ **RX 打通了** | → 步骤 3 |
| `edges > 0` 但 `rxIrq == 0` | 信号到了但中断没进 | → 步骤 2A |
| **`edges == 0`** | 信号仍未到 PA10 | → 步骤 2B |

---

### 步骤 2A：`edges > 0` 但 `rxIrq == 0`（软件/中断）

说明电平变化能被 GPIO 采样到，但 USART1 没产生中断。可能原因：
- 波特率不匹配（PC 侧不是 115200）
- 电平极性 / 空闲态被拉偏（幅度不够、被 485 或其它模块拉低）
- NVIC 优先级/抢占问题

**动作**：检查 PC 侧波特率 = 115200 8N1；用示波器/逻辑分析仪看 PA10 波形幅度是否到 3.3V。
若幅度不足 → 考虑模块是 5V 输出（需电平转换或改 3.3V 跳线）。

---

### 步骤 2B：`edges == 0`（信号没到 PA10）⭐ 最可能

**逐项排查（按成本从低到高）**：

| # | 检查 | 方法 |
|---|---|---|
| 1 | **TX/RX 是否接反** | 换一次：模块 TXD→PA9、RXD→PA10 试试（虽然按规范是交叉，但先排除） |
| 2 | **杜邦线断路/接触不良** | 万用表通断档：模块排针 ↔ J4 排针，逐根量 |
| 3 | **接错引脚** | 确认接的是 **J4 pin5（PA10）/ pin6（PA9）**，不是 J1 上其它脚 |
| 4 | **模块本身坏了** | 用**回路法**测：把模块的 TXD 和 RXD 短接，用串口助手发字符，看是否原样收回 |
| 5 | **没共地** | 万用表量模块 GND ↔ 板 GND，必须导通 |
| 6 | **确认焊点** | J4 若是自己焊的排针，检查是否虚焊 |
| 7 | **换一块板试** | 同样接线换到板2（COM5），若板2通 → 板1 的 J4 焊接/走线问题 |

> **回路法（第 4 项）判据**：短接 TXD-RXD 后自发自收成功 = 模块好；
> 失败 = 模块坏，直接换一个。

## 七、风险提示

| 风险 | 说明 | 对策 |
|---|---|---|
| **接错 VCC 到 PA9/PA10** | 5V 灌进 MCU IO 可能损坏芯片 | 先拔掉所有电源线，只留 TXD/RXD/GND |
| **DTR/RTS 反复复位** | 每次开串口都复位，干扰诊断 | 强制 `dtr/rts=False`；物理上拔掉这两根 |
| **板子另有供电时又接 5V** | 双电源倒灌 | 只保留一路供电（ST-Link 供电或 USB-TTL 供电，二选一）|
